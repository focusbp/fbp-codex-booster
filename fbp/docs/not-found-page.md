# 404ページ

システム設定の「ルートアクセス時のリライト」の下にある「404ページ」でClassとFunctionを指定する。設定キーは `not_found_class` と `not_found_function`。両方未設定の場合、従来どおり404・text/plainの `Not Found` を返す。

通常のGET・HEADでクラスや関数が見つからない場合に、設定先を内部実行する。URLは変えず、最終ステータスは404に固定する。HEADでは本文を出さない。POST・appcon・XMLHttpRequest・JSON要求・API/MCP宛ての呼出しにはカスタムHTMLを適用しない。既存のAPI独自応答は変更しない。

設定先は表示専用の公開関数とし、コンストラクタで `set_check_login(false)` を明示する。管理画面の認証は迂回しない。設定先の不存在・非公開メソッド・空出力・例外・再帰は標準404へ戻り、途中出力は破棄する。通常テンプレートは `show_public_pages()` で表示できる。

アプリが明示的に404にする場合は `$ctl->res_not_found()` を呼ぶ。呼出し後はレスポンスを終了するため、JSONの追記や後続処理は発生しない。

Webサーバーが直接処理する静的ファイルの404には適用しない。対象はフレームワークへ到達するページリクエスト。

検証: 応答ヘルパー16項目、実HTTPで設定先の正常・不存在・非公開・認証必須・再帰・例外・未設定、JSON/XHR/POST/HEAD、設定画面の表示を確認。アプリではPC・スマートフォンの404・キャラクター・フロントページリンクを確認。
