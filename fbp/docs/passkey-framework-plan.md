# パスキー共通化計画

## 現在の合意と状態（2026-11-07）

app-soshikikaikakuで安定している実装を基準に共通化する。旧Cookie・ログイン済みセッションを引き継ぐための独自互換処理は追加しない。失効世代を持たない旧remember-meや管理セッションは再ログインが必要になる。既存ユーザー情報・パスワードと、実証済み実装に元からある認証処理は保持する。

共通実装とapp-fwtestでの検証を完了。本番framework配布、他アプリの設定生成・一括有効化、app-soshikikaikakuの独自実装撤去は未実施。実証アプリは引き続き従来の独自クラスを使う。

## 完了した前提整理

- FOCUS2の独自user・login・password_resetを保持し、パスキー入口をアプリ側で拒否する。認証独立化r1084を同じcode_dirの本番17環境へ配布・確認済み。
- app-waaは施設・出品者の独自user・loginを維持し、password_resetを独自配置、パスキー入口を拒否。r108を本番反映・確認済み。
- app-movingbaseは独自userを撤去して標準版を利用。既存ユーザーの基本7項目保持と固定形式拡張を検証し、r1266を本番反映・確認済み。
- 対象アプリ・配布先数は実施時に管理台帳から再確定する。本番のDB定義・メールテンプレート・既存業務データは各配布の保持条件に従う。

## 共通版の構成

- app/passkeyへ登録・認証・鍵管理、パスワード認証停止・再認証、別端末登録、通知、専用CLI復旧、固定fmt、依存ライブラリを移植。既存userの固定形式は変更しない。
- 標準login・password_resetへ実証版の差分を統合。パスキーDBは固定DSPで保護し、認証済み管理APIの既存例外と専用復旧の条件を保持する。
- 旧セッション失効の確認は、実行時に標準loginが選ばれる場合だけ管理アクセスへ接続する。FOCUS2・Waa等の独自loginではその確認を行わず、独自認証・独自DSPを保持する。アプリ名一覧や機能フラグによる複雑な除外分岐は設けない。PASSKEY_ENABLED=falseは既存の明示マーカーとして残るが、共通版の除外判定はクラス配置に基づく。
- 標準userからの削除では、参加DBを先に開いて最新ユーザーを再確認し、全RPの鍵を失効してidentityを除去する。同じIDの再作成でも旧ハンドル・停止設定を引き継がない。

## 設定

- 各アプリのclasses/app/passkey/config.phpを正本とし、共通コードの配布では上書きしない。サンプルはapp/passkey/config.example.php。設定のみを置き、共通版を使うアプリにはpasskey.phpを追加しない。
- app_code、本番／テスト別enabled、許可hosts、TLS終端の信頼peerを明示設定する。未設定・無効・不正ホスト・HTTPS条件不成立ではパスキー利用不可。
- RP IDは許可済みアクセス先ホスト、originはそのHTTPS originとの完全一致。任意Hostや転送ヘッダーで許可を拡張しない。異なるドメインは別RPとして各サイトで登録する。Related Origin Requestsは対象外。
- app-fwtestはテストだけ有効、本番設定は無効。一般アプリへの設定生成・配布は後段で行い、リクエストごとに管理台帳へ問い合わせない。

## 検証結果

- 既存の実署名・実FFM試験を共通配置に合わせて移植。改ざん、期限・用途・origin・RP・UV・handle不一致、再送、失効鍵、所有者外操作、同時認証、復旧、認証停止、旧形式identity拡張、旧管理セッション拒否に合格。
- app-fwtestの実ブラウザーで、通常ログインからの案内、登録ウィザード、誤パスワード、キャンセル・再試行、複数鍵、完全ログアウトからのパスキー認証、失効鍵拒否と残る鍵の利用、PC／スマートフォン表示を確認。仮想認証器の試験鍵は削除。登録通知先メールが未設定の試験ユーザーを使用し、実メールは送っていない。
- 隔離HTTP環境で認証停止・パスキー再認証・最後の鍵の保護、別端末登録URLと確認コードを確認。通知はキャプチャで検証し、メール送信なし。
- 専用CLIを隔離した実runtimeで起動し、YES成功、NO・小文字・空白付き・EOF中止、存在しないID・非管理者・通常app_callからの拒否、全RP失効、userとパスワード保持、標準user削除による鍵・identity失効を確認。実HTTPでCLIファイルへの直接アクセス403も確認。
- 更新済みframeworkのテスト環境でFOCUS2・Waaの既存単体試験と実ログイン・管理画面・独自パスワード変更・パスキー404を確認。両アプリの実アカウント・権限・メール設定は変更していない。

## 次の工程

1. 共通版の内容と検証結果を確認し、本番framework配布とアプリ設定配布の対象を確定する。
2. app-soshikikaikakuを同一データ・RP ID・user handle・epochを保持して共通版へ切替検証し、重複する独自実装と専用DSP／ガードを整理する。
3. 条件を満たす標準認証アプリへ設定を配布し、一括有効化する。FOCUS2・Waaは対象から除外する。
4. 共通版の動作確認後、FOCUS2独自認証へのパスキー追加を別工程で進める。

認証停止済みユーザーのパスワード認証を、機能無効化だけで自動再開しない。切り戻しでは認証経路と専用CLI復旧を確認する。本番反映は承認済み運用手順による別工程とする。
