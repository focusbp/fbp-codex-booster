# Public Admin Portal UI Sample

Use this reference when `public_pages` needs a management-screen-like public portal, such as an FC store portal, member work console, shop back office, or partner dashboard.

The pattern is quiet and operational: top bar, left menu, dense main content, summary counters, searchable list, compact Material Symbols buttons, and no landing-page hero. It should feel like a real CRUD tool.

## Principles

- Use `show_public_pages()` for the shell and keep the first screen as the actual tool.
- After the initial public URL, do not change the browser URL. Use `ajax-link` / `ajax-button`, `reload_area()`, and dialogs for internal navigation, search, save, delete, and paging.
- Store the public context, such as `fc_store_id`, in session at the entry function. Do not keep passing the identifier through internal links.
- Display the current context in the top bar, for example the logged-in FC store name.
- Use Material Symbols actively for actions and navigation.
- Good Material Symbols placement: top-bar context (`storefront`), logout (`logout`), left menu (`dashboard`, `support_agent`, etc.), search/filter (`search`, `filter_list`), summary cards (`inbox`, `payments`), and compact row actions (`edit_square`, `delete`).
- Use icon-only buttons for dense row actions; use icon+text buttons for primary commands where the command should be explicit.
- Do not include a read-only "view/reference" row action unless the workflow truly needs it. Default row actions are edit and delete.
- Keep icon button base sizing flexible. Do not force width/height on the generic icon button; set height only on specific variants when needed.
- Use `fields_form_direct` for DB-backed fields and `fields_form_original` for non-DB form fields when the field helper is suitable. Use `fields_view_direct` for list/display cells that should follow DB field formatting.
- Put lists behind a partial template and use `ajax-auto` for incremental loading when the list can grow.
- When showing child records such as estimate items, invoice items, history comments, or schedule rows, put a compact parent summary panel directly above the child list.
- Use the Control CSS Baseline below for appstyle resets, dropdowns, labels, datetime alignment, and Material Symbols colors.

## Control CSS Baseline

- Reset `appstyle.css` button margins inside the public page root: `button { margin: 0; }`.
- Reset dropdowns inside the public page root as well. `appstyle.css` gives normal `select` and FBP original select buttons thick borders, large padding, and top margins.
- Override both native `select` and `.fbp-original-select-button`; FBP may replace a `select` with the original-select button after rendering.
- Keep native and original-select controls compact: `height: 38px`, `border: 1px solid #cbd5e1`, `margin: 0`, `font-size: 13px`, and `line-height: 36px`.
- Use `margin-bottom: 1px` for compact manual form labels.
- Use `margin: 0 0 5px` for `.field_edit h6` labels generated by `fields_form_direct`.
- When aligning `fields_form_direct` datetime fields beside dropdowns, add `margin-top: 5px` to `.wrap_datetime` inside the public form scope.
- Material Symbols inside dark/primary command buttons must explicitly be white (`#fff`). Row action icon buttons may inherit muted/danger colors.

## Controller Data Shape

```php
private function assignPortalDesign(Controller $ctl, array $store): void {
	$store_name = trim((string) ($store["name"] ?? ""));
	if ($store_name === "") {
		$store_name = "店舗";
	}
	$ctl->assign("store_name", $store_name);
	$ctl->assign("portal_menus", [
		["icon" => "dashboard", "label" => "ダッシュボード", "active" => true],
		["icon" => "support_agent", "label" => "受付"],
		["icon" => "request_quote", "label" => "見積"],
		["icon" => "receipt_long", "label" => "請求"],
		["icon" => "account_balance", "label" => "入金"],
		["icon" => "assignment", "label" => "預り証"],
		["icon" => "calendar_month", "label" => "スケジュール"],
		["icon" => "draw", "label" => "作業報告"],
	]);
	$ctl->assign("summary_cards", [
		["label" => "受付中", "value" => "12", "tone" => "teal", "icon" => "inbox"],
		["label" => "見積待ち", "value" => "5", "tone" => "amber", "icon" => "pending_actions"],

	]);
	$ctl->assign("rows", $rows);
}
```

## Parent Summary Above Child List

Use this pattern when a child list is scoped by a parent record: estimate items under a repair case, invoice details under an estimate, comments under a case, or stock movements under a part.

- Put one parent summary panel immediately above the child list.
- Prefer a horizontal-line detail table over small cards when the parent data is factual and compact.
- Keep the parent status as a compact pill in the panel header when useful.
- Show only the parent fields needed to work on the child list: ID, date, customer/name, contact, object/device, and request/notes.
- Avoid heavy boxed cards inside the panel; use row borders, clear labels, and two label/value pairs per row on desktop.
- On mobile, stack each label/value pair using `display: block`.
- If the child page is loaded by `reload_area()`, place the parent-summary CSS in the partial template or ensure it already exists in the shell. Ajax-loaded content should not depend on a full page reload for critical layout.

## Implementation Notes

- `public-admin-icon-button` intentionally has no fixed width or height in the base class. Row actions set only a compact height on the row variant.
- Keep a scoped `button { margin: 0; }` reset because app-level `appstyle.css` may add top margins to buttons.
- For dropdowns, override both native `select` and `.fbp-original-select-button`; FBP may replace a `select` with the original-select button after the dialog is rendered.
- If a datetime field rendered by `fields_form_direct` sits slightly higher than adjacent controls, add `margin-top: 5px` to `.wrap_datetime` in the public form scope.
- For long lists, keep search state in the form/session and append `ajax-auto` at the end of the partial list template. Use `increment_post_value("max", <page size>)` in the list action.
- If a detail view is required later, open it through edit or a tab/panel state instead of adding a separate "view" icon by default.
- The sample is a design starting point; replace sample arrays with DB rows and encrypted IDs before wiring real CRUD actions.
