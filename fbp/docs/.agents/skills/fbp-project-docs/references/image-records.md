# 画像案件の保存・サポート記録

プロジェクトに属する画像生成・編集・合成の納品では、次の修正担当が元画像と現行版を特定できる状態を残す。単発のプレビューや不採用案を一律に保存する必要はない。対象プロジェクトは通常の解決手順で確認し、推測で保存先を決めない。

## 保存先と版

- 既存の保管規約があれば従う。なければ編集元プロジェクトの `assets/image-work/task-<ID>/` を使う。Taskがない場合は短い案件名を使う。docsには履歴と参照だけを置く。
- 元画像、参考画像、修正指示入り画像、実際に使用したマスク・差し込み素材、採用した完成画像、処理設定を保存する。未使用マスクや取得できない内部情報を作らない。
- 元画像と納品済み画像は保持し、修正は `final-v01.png`、`final-v02.png` のように別版にする。生成ツールの保存先や作業用一時領域だけに残さない。
- この保管フォルダは編集素材用であり、自動的な公開・サイト組込み・本番配布の対象にしない。納品ZIPには依頼された成果物だけを収録する。

## manifest.json

案件フォルダに以下を記録する。パスはmanifest基準の相対パスとし、ファイル名だけで役割を推測させない。

- 案件の目的、Task ID（存在する場合）、更新日時。
- 各ファイルの役割：original / reference / instructions / mask / material / final / config。
- 各完成版の修正元ファイル、参照した指示画像、使用素材・マスク・設定ファイル。
- 実際に使った指示文とツール名、取得できた設定値。AI生成は同じ指示でも同一結果を保証しないため、採用出力そのものを保持する。
- 反映した変更点、目視確認した項目、未確認事項。
- 作成済み・未納品／納品済みなどの状態、現行納品版、次の編集の基準画像。最後の添付が編集対象とは限らない。
- 納品成功後の添付コメントIDと納品日時。投稿失敗時は未納品のままとし、成功を推測しない。

秘匿値、Cookie、署名付き・期限付きURL、環境固有の接続先、ローカル絶対パスを含めない。ツール出力のreportを保存する場合も内容を点検し、必要な情報を相対パスへ整理する。顧客素材の取扱条件がある場合はそれに従う。

## 作業・納品・履歴

1. 前回のmanifestとサポート履歴を確認し、元画像・指示画像・現行版を実物で照合する。画像の修正依頼を、注釈の焼き込み依頼へ置き換えない。
2. 必要な入力を保持して処理し、新版と処理メタ情報を保存する。既存の完成版が依頼を満たすなら再生成せず利用できる。
3. 指示の反映、文字、不要な赤字・囲みの残り、全体の見た目を確認する。指示確認用画像を作る場合は納品完成版と明確に区別する。
4. 許可された範囲で成果物を添付し、成功後にmanifestの納品情報を更新する。この保存規約自体はコメント投稿・status変更・本番反映の許可を追加しない。
5. `docs/history.md`へ、Task ID、変更点、manifestへの相対リンク、現行納品ファイル、添付コメントID、確認結果・残件を1〜2項目で残す。未納品の場合はその状態を記す。画像・指示文・設定の全文は重複掲載しない。

例：Task 4742：英文書体と商品サムネイルを修正。目視確認済み。現行納品版は final-v02.png、コメント12090。入力・処理設定は案件manifestへの相対リンクを参照。
