# 管理一覧のレスポンシブCSS方針

標準画面で実装済みの方針を、独自画面でも再利用するときの基準。実装の正本は `fbp/css/appstyle.css` の Standard Screen search/list 節、`fbp/app/db_exe/Templates/index.tpl`、`fbp/app/base/Templates/index.tpl`。

標準画面のスマホ対応は「標準画面レスポンシブ」設定と既存の共通CSSを使う。本書を根拠に標準画面用のCSSを案件側へ複製しない。新規管理画面もスマホ利用を前提にするが、既存のパソコン表示指定や設定変更の作業範囲を尊重する。

## 適用条件と範囲

- 管理画面の `body.fbp-standard-responsive` と `@media (max-width: 700px)` の両方を条件にする。`standard_screen_responsive=0` がレスポンシブ、`1` がパソコン。未設定・不正値の正規化はframeworkに任せ、画面ごとに設定を読み直したりbodyのクラスを書き換えたりしない。
- パソコン設定では狭い画面でも表形式と既存の最小幅を維持する。レスポンシブ時も701px以上では表形式へ戻る。Viewportは既存設定を維持し、端末名やJavaScriptの初期幅で表示を固定しない。
- 標準画面は `.db_exe_responsive_list` があるメイン一覧だけを対象とする。独自画面には専用マーカーを設ける。`body` / `.content` / `#work_area` の幅補正も、そのマーカーがメイン画面にあるときだけ適用する。
- 公開・ログイン画面、カレンダー、単一レコード、子サイドパネル、ダイアログ内の表は一覧カード化の対象外。それぞれの用途に必要なレイアウトを別に設計する。

## 一覧と操作

- 1レコードを1カードにし、各セルを「項目名＋値」の2列にする。標準の目安は `grid-template-columns: 86px minmax(0, 1fr)`、余白10px、カード間12px、境界線と角丸6px。
- 項目名と値はDOM内の `.row_title` / `.row_value` に保持する。同じ行をPC・スマホで使い、別々のデータ・操作要素を複製しない。既存のthead型を移す場合はセル内にも項目名を用意する。
- テーブル・tbody・trはモバイルでblock、通常セルはgrid。固定幅の列はモバイルだけ解除する。値には `min-width:0; white-space:normal; overflow-wrap:anywhere` を使う。リンク・メール・長文・選択肢ラベルも親幅内で折り返す。
- 操作セル・ソートセル・空一覧のcolspanセルは通常セルと区別する。操作行は折り返し可能にしてfloatを解除し、アイコンボタンには操作名と十分な押下領域を持たせる。標準の行操作は最小38px、共通ヘッダー操作は44px。
- 通常のレコード一覧ではカード表示を優先する。多列という理由だけで全面的な横スクロールへ逃がさない。列間比較が業務上必要な集計・時系列・マトリクスは、理由を明記したうえでその表のラッパー内だけ横スクロールにできる。ページ全体のはみ出しを `overflow-x:hidden` で隠さない。

## 検索・入力・再描画

- モバイルでは検索条件を1列にし、日付・日時の開始／終了も上下に並べる。入力部品はhelperを使い、親のgrid/flexには `min-width:0` を指定する。
- 検索可能selectの `.fbp-original-select-wrap` はCSSで親幅に追従させる。元selectのインライン幅・計算済み幅をJavaScriptでコピーしない。個別幅が必要ならフィールドのコンテナに指定する。
- Ajaxの検索・追加読込・更新後もマーカー、項目名、操作クラスを保持する。CSSは画面の外枠で一度読み込み、更新される行ごとに重複させない。
- ソート中の幅固定は表形式のドラッグ用複製だけに行う。元行へ固定幅を残さず、幅だけでなく実際のtable/card表示を見て判断する。

独自画面への組込みは [fbp-original-screen の手順](../../fbp-original-screen/references/responsive-layout.md) とサンプルを使う。標準画面用クラスを付けるだけで独自の検索・権限・CRUDが標準化されるわけではない。
