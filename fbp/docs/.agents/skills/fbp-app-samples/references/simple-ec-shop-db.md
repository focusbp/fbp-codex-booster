# Simple EC Shop — DBと画面

全ノートは `sec_` 接頭辞を使う。業務データ・ユーザー・認証情報を含まず、導入ツールは定義だけを登録する。
完全な項目・型・長さ・画面順は `assets/simple-ec-shop/simple-ec-shop.json` を正本とする。

| ノート | 主な内容 | 管理画面 |
|---|---|---|
| `sec_shops` | 公開コード、内部ショップ識別子、表示状態、送料、共通決済の使用有無、店舗・特商法情報、画像 | 一覧＋専用追加・編集ダイアログ、公開リンク、商品／カテゴリーのサイドパネル |
| `sec_products` | 種別、商品名、説明・画像、種類1〜5、価格・税率、在庫上限、開催日時、定期購入条件 | ショップ配下の一覧、種別別の追加・編集ダイアログ |
| `sec_categories` | ショップ・カテゴリー名・並び順 | ショップ配下の標準サイドパネル |
| `sec_orders` | 受注番号・注文日時、申込者、送付先、状態、税込合計、送料・税、受付キー | 標準一覧・検索・編集、明細・帳票・CSV |
| `sec_items` | 受注・商品参照、注文時の商品名・種類・個数・単価 | 受注明細 |
| `sec_contracts` | 契約者、注文時の月額、状態、課金開始・前回決済・終了日、カードリンク用トークン | キー4があるときだけ契約メニュー、編集・決済履歴・カードリンク |
| `sec_payments` | 注文／契約参照、環境、対象月、金額・結果、Square決済ID、返金状態・キー | 決済履歴、確認付き全額返金 |
| `sec_runtime` | 受付・決済、通知、定期処理の各スイッチ、定期課金開始日 | Standard Screen／単一レコード。行IDを固定しない |
| `sec_outbox` | 宛先・件名・本文、イベントキー、送信状態 | 通知履歴。通常の再実行は送信済みを再送しない |
| `sec_secrets` | 注文／契約のSquare顧客・カード参照 | 内部専用。メニュー・直接CRUDを拒否 |

## 種別の選択肢

商品と受注のtypeは同じ `sec_product_types` を参照する。
意味は **0=物販、1=イベント、2=問い合わせ、3=見積依頼、4=定期購入** と固定する。
導入時は必要なキーだけを登録し、ラベルの変更は可能。欠番を詰めない。
サブスクリプションのメニュー可否、保存・公開受付・決済・cronも同じ登録内容を判定する。
登録済みキー以外の値はサーバー側で拒否する。

## 金額・氏名・状態

- 金額はJPYの整数。税別単価×個数に商品税率を適用し、明細ごとに切捨て、物販のカートにショップ送料を加算する。
- `sec_orders.from_name` は「申込者氏名」、`sec_orders.name` は「送付先名称」。住所・電話もそれぞれ独立させ、納品書と領収書の宛名を区別する。
- 受注状態は0=決済待ち、1=発送・対応待ち、2=対応済み、3=キャンセル、4=返金処理完了。
- 銀行振込は状態0で受付。Squareは決済成功を確認して状態1とし、未完了時は通知を送らない。
- 契約状態は0=未処理、1=契約中、2=エラー、3=カード登録待ち、9=終了。
- 決済状態は0=決済済み、1=エラー、2=返金済み。`state`／`environment`／`period`で処理段階と対象を区別する。

## 内部データと並行処理

- `record_key` は注文・契約・カード参照の内部キー。`metadata_json` は受注構築の完了判定用で、申込者から編集させない。
- データ参照先・親子関係・注文金額を、直接POSTされた値から採用しない。商品・ショップ・確認時の見積りから再計算する。
- 関連ノートを先に開いてから照合・保存・外部処理へ進む。独自のflockや外部ロックファイルを使わない。
- 通常決済は注文キー、定期決済は契約固有キーと対象月、返金は保存した返金キーで重複を防ぐ。
- 契約固有キーは申込時のランダムな受付キーから作る。同じSquareアカウントを複数アプリで使っても、ローカルの契約IDが同じという理由で課金キーが衝突しない。
- API送信前に結果不明の状態を保存する。確定できない結果は自動再課金しない。
- 通知は送信中を保存してから配送し、SMTPの結果不明は履歴へ残す。決済を失敗に戻さない。

## 管理者と初期状態

FBPのAdminユーザーだけが管理機能を使う。特定ログインIDや元案件の担当者には依存しない。
公開受付は未ログインで使えるが、CSRF・セッション内カート・確認内容の署名・二重送信キーを検査する。
設定が空の状態は受付・通知・定期処理とも無効。初回表示だけでは設定レコードを作らない。
Square・メール接続情報は各アプリの共通設定で管理し、このmanifestや業務ノートへ同梱しない。
