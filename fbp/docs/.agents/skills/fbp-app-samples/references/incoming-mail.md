# Incoming Mail

アプリ独自の受信アカウントを登録し、未確定メールを受信メールノートへ保存してから確定するサンプル。SMTP送信やシステム設定の受信アカウントは変更しない。

## 導入

`assets/incoming-mail/incoming-mail.json` がコード・ノート・項目・画面・ボタン・選択肢の正本。

```sh
php "$SKILL_ROOT/scripts/install_incoming_mail.php" --code-root="$SOURCE_ROOT"
# 環境の正規手順でソースからテスト実行先へ同期する。
php "$SKILL_ROOT/scripts/install_incoming_mail.php" --configure-test-root="$TEST_ROOT"
```

配置先は存在するアプリのルートを指定する。同名クラス・ノート・選択肢の既存実装があれば停止する。インストーラーはデータ、認証情報、cronを登録しない。定義途中の失敗は成功済み項目を確認して復旧し、初期化や盲目的な再実行をしない。

1. 管理者で「サンプル：受信アカウント」に名称を登録。初期状態は停止。
2. 行の「接続設定」でPOP／IMAP・サーバー・ポート・暗号化・認証情報・フォルダーを保存。パスワードは`$ctl->encrypt()`で暗号化し、空欄保存は保持する。設定ダイアログにパスワードや受信状態を再表示しない。
3. 受信を有効にして「今すぐ受信」。取得メールを「サンプル：受信メール」へ保存する。
4. 定期実行が必要なアプリで [fbp-cron](../../fbp-cron/SKILL.md) に従い `sample_mail_import::cron` を登録する。処理入口は検証済みcron主体のみ受け付け、アプリ導入だけでは周期を決めない。

## 処理内容

- `$ctl->receive_mail(20, ['table'=>'sample_mail_accounts', 'id'=>$id, 'password_encrypted'=>true])` を使用する。確定にも同じ指定を渡す。
- 設定DB・アカウントDB・受信メールDBを事前に開き、FFMのロック順序が確定してから読む。受信識別情報のSHA-256で重複確認→ノート保存→処理済み確定。確定直前に中断しても、再実行時は既存レコードを確認して再確定する。
- サンプルは件名・差出人・プレーン本文・添付名・保存日時を保持する。HTML表示、raw保存、添付内容のファイル保存、サーバー上の自動削除は含めない。必要な案件では [fbp-receive-mail](../../fbp-receive-mail/SKILL.md) と媒体保存方式に合わせて拡張する。
- 保存長を超えるメールは切り捨てず例外にして未確定のまま残す。繰返し止まるメールの対応方針はアプリで決める。
- 管理画面は管理者のみ。受信メールは一覧・検索専用。アカウントの内部項目への標準画面からの偽装POSTや削除・複製は拒否する。一般ユーザーへの公開や汎用API経由の権限も必要なら、案件のDSPを設計する。
- アカウントを変更すると受信状態を流用せず再取得する。同じメールでも新しい接続設定のIDは異なるため、アカウント切替をまたぐ業務上の重複照合が必要ならMessage-ID等の追加方針を設計する。

## 検証

```sh
php "$SKILL_ROOT/scripts/test_incoming_mail.php" "$EMPTY_SCRATCH_DIR"
```

空の作業ディレクトリで権限・偽装入力・コード配置・上書き拒否を確認する。外部接続や実データを使用しない。


インストーラーの空ディレクトリへのコード配置・上書き拒否・manifest解析、PHP lint、定義登録、Standard Screenの入口・接続設定保存・偽装／非管理者拒否を確認する。未使用add/edit/delete/list_on_sideの警告は意図したもの。実受信はテスト専用アカウントで、日本語メール保存・再実行時の重複なし・システム設定の受信状態保持・暗号化パスワード保持を確認する。既存メールを無断で削除する検証を追加しない。
