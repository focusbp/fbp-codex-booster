# ノートに追加する7機能サンプル

CSVアップロード、CSVダウンロード、PDF一覧印刷、MCP連携、公開フォーム、単品ショップ、AI-OCRの最小フローをまとめた再利用例。AIへの機能追加依頼を実装する際の出発点にする。機能を選択してタスク登録する「＋」UIそのものは含まない。

## 導入

- 正本は `assets/note-feature-samples/`。商品コード・商品名・円価格・補足の架空商品をCSV/PDF/MCP/ショップで共用する。実案件の項目へ適応する際は下記の必要情報を確定する。
- `scripts/install_note_feature_samples.php --code-root=<source-root> --ocr-table=<existing-excel-note>` はコードだけを配置する。既存クラス、とくに `public_pages` の上書きを拒否する。既存公開ページがあれば必要な関数・テンプレートだけ統合する。
- 環境所定の方法でソースからテストへ同期した後、`python3 scripts/configure_note_feature_samples.py --test-root=<web-test-root> --receipt=<private-receipt-file>` でDeveloper Modeのノート・項目・標準画面・上部ボタンを作成する。架空商品3件も必要な場合だけ `--with-sample-data` を追加する。既存ノートやreceiptがあれば停止し、部分完了を調べてから復旧する。
- OCR対象は既存Excelノート。Developer Modeでも通常のExcel画面・CLIから新規作成・列変更ができる。例外処理やモード変更は不要。実運用で変更された列は通常の取得・取込み手順でテストへ反映する。
- OCRのExcel上部ボタンは対象ノートの `db_additionals place=0` から `feature_excel_ocr::run` を呼ぶ。商品サンプルのボタンは `feature_products_ocr` を通じて商品ノート自身を対象にする。対象ノートごとに列定義とセッションを分け、他のノートへ保存しない。
- `mcp-functions.json` を通常のMCP登録手順でdry-runしてから適用し、単一サーバーをOAuth・`fbp_user`・`mcp.read`で設定する。認証を無効にしない。
- [DB・画面構成](note-feature-samples-db.md)と各機能のSkillを併用する。

## 機能別の必要情報と既定動作

| 機能 | 先に把握する情報 | このサンプルの範囲 |

| CSVダウンロード | 対象ノート、対象行/項目、見出し、文字コード、閲覧権限 | 管理ログイン下の全商品、現在の表示列順・項目名、UTF-8、数式注入対策あり |
| PDF一覧印刷 | 対象ノート、対象行/列、用紙、タイトル、閲覧権限 | 管理ダイアログ→POST→A4一覧PDF、現在の表示列順、数値右寄せ |
| MCP | 操作、入出力、権限、利用者主体、確認の要否 | OAuth・mcp.read、商品読取りのみ、limit 1〜100 |
| 公開フォーム | 受付先、入力項目、必須/型、確認/完了、公開範囲 | 名前・メール・内容→確認→保存、通知メールなし |
| 単品ショップ | 商品、価格、数量、購入者/配送先、決済環境、結果管理 | 1商品、数量1〜99、円、Square Sandbox決済、メール/配送/返金なし |
| AI-OCR | 対象Excelノート、現在の列定義、画像、保存単位 | 列名・型・選択肢を動的取得、1画像→1行、確認修正後に追加 |

## 動的OCR

- Excel風ノートは `ExcelGrid::config()` が列の正本。通常ノートは `get_field_list(<対象ノート>, "add")` の現在の入力項目・型・選択肢を使う。固定の商品項目リストや、別ノートの列定義は使わない。通常ノートの項目変更は追加画面にも反映する。
- 生成済みの入力列だけから抽出指示と型別確認フォームを組み立てる。列追加・名称・型・選択肢の変更は画面を開き直すと反映する。計算・関数列、未使用列はAI入力・保存対象外。
- 定義のfingerprintを受付時・読取り時・保存時に照合し、処理途中の定義変更を拒否する。AIの未知キーは破棄し、保存値は現在の型と選択肢で再検証する。
- 保存は新規1行。既存行を上書きしない。保存後はExcelの計算・同期post_actionを実行し、計算失敗と入力保存済みを区別する。再送で入力を重複登録しない。
- 商品用の派生クラスはノート名だけを結び付け、抽出・確認フォーム・保存は共通処理。内部項目と未対応型は対象外とし、通常ノートの保存では標準検証も実行する。
- サンプルのOCR入口は管理者専用。一般利用者へ広げる場合はノート・行・項目の業務権限を既存の可視性/DSPと合わせる。管理者ガードを外すだけで配布しない。
- PNG/JPEG、5MB、最大2000万画素。画像は確認操作でOpenAIへ送信し、読み取り用にアプリの永続保存はしない。既存 `chatGPT_image_analysis()` と外部連携設定を使う。実画像精度は帳票ごとに確認する。

## Square Sandbox

`force_testmode=1`、テストセッション、Sandbox Application ID、アクセストークン、Location IDがそろう場合だけ決済できる。商品価格はサーバーで再取得し、確認後の価格変更を拒否する。決済金額と通貨・COMPLETED・決済IDを照合する。

注文を `pending → processing → unknown → paid` と進め、結果不明では再課金しない。成功済みのcallback再送でも再課金しない。結果不明・失敗の注文は管理側で確認する。自動再試行や本番決済への切替は含まない。

## 共通の項目順

`feature_product_schema::fields()` をCSV・PDF・MCP・ショップ入力の共通入口とする。Excelでは実行時の列定義と `column_order`、通常ノートでは追加画面の項目順を使う。OCRも同じ実行時定義と列順を使う。CSVヘッダーは現在の項目タイトル。MCPは表示順の `columns` と、その項目IDをキーにした `items` を返す。

商品コード・商品名・価格という業務上の意味は `roles()` で安定した項目IDへ対応付ける。Excelサンプルではa/b/c/d、通常ノートではcode/name/price/memo。表示位置から意味を推測しない。実案件へ適応するときは役割の対応付けを明示する。

専用検証アプリの商品サンプルは利用者が承認した移行例外でExcel化し、既存5件を保持した。初期表示はコード→商品名→価格→補足。列移動後のCSV実入出力、PDF、MCP、OCR、ショップ表示と価格の意味の保持を確認した。共通インストーラーに特例の保護回避処理は含めず、通常のExcel定義操作・接続手順を使う。通常ノートからの汎用的な自動Excel変換機能を実装したものではない。

Developer Modeの定義変更禁止は後続の利用者指示で撤廃済み。以後の作成・項目変更・標準画面からの変更は通常作業とする。本番同期は本番→テスト、定義配布はテスト→本番。本番同期で開発変更が消えることは許容するが、リリース直前に自動同期して開発変更を消さない。

## ページボタンとショップの調整（2026-10-30）

- Excel風のページボタンを右寄せにし、標準画面と同じ定義順・右フロートで表示する。
- 公開フォーム・単品ショップ・MCP連携を独立したページボタンと案内に分割。PDFは認証付きPOSTを維持し、別タブへinlineで表示する。
- 単品ショップは商品ノートから独立した固定商品「サンプルノート」、単価1,200円を表示・確認・注文・決済に使う。ショップ画面のSandboxに関する説明文を削除。Sandbox限定の決済制御は維持する。

- ショップの購入入力は対象ノートの入力項目・型・順序へ動的に追随する。固定の氏名・住所・数量欄は設けず、ノートに数量があれば他の項目と同じ入力欄として表示する。金額は固定1,200円で、入力した価格・数量から計算しない。確認時の項目名と値を注文の「入力内容」に保存し、定義変更時は再入力を促す。
- Developer Mode等で表示していたノート設定ショートカットを一覧・Excel・カレンダー・単票・子一覧・追加編集削除の共通テンプレートから削除。開発パネルの編集機能は維持。

## OCR複数件・MCP CRUD（2026-10-30）

- OCRのファイル選択と同じ画面で1件/複数件を選択。複数件は最大20件、行ごとに確認・修正。説明文と対象項目の列挙は表示しない。全行を検証してから保存し、再実行による重複挿入を防止する。
- MCPは検索（一覧）・追加・変更・削除の4関数を初期登録する。検索はqueryの部分一致と行IDを返す。変更操作は管理者のOAuth subject、mcp.write、confirm=trueが必要。入力項目以外は拒否し、変更後の計算・関数を実行する。案内には関数名・取得件数の説明を表示しない。
- 実画像から2行のOCR抽出・編集画面、OAuth経由の追加・検索・変更・削除を確認。検証用MCP行は削除し、トークンは失効。隔離検証39項目で単件・複数件保存、保存前全行検証、再保存拒否、MCPの認証・確認・項目制限を確認。

## メール送信・受信のExcel風サンプル（2026-10-30）

- 「サンプル：メール送信」は氏名・メールアドレスの順で、ページ上部の「メール送信」からリスト全体のメールアドレスを重複排除し、件名・本文と全宛先を確認して1件ずつ送信する。prepared-formatメールを使い、システム設定のテスト送信先は不要。操作ログで二重送信を防ぎ、不確かな失敗はunknownとして再送を拒否する。
- 「サンプル：メール受信」は日付・タイトル・内容の順。内容はtextarea・3,000バイト。上部の「メール受信」からシステム設定の受信アカウントで最大20件を取得する。保存前に件名255バイト・内容3,000バイト・日付を検証し、保存後に処理済み確定。受信識別キーを非表示の内部項目で保持し、中断後の再実行でも重複しない。メールサーバー上の削除やcron登録は行わない。
- 追加ノートの導入は `configure_note_mail_samples.py` を明示したテスト環境で使う。既存ノートの上書きは拒否し、途中失敗はreceiptを確認してresumeする。認証情報・サンプル宛先データは自動投入しない。
- 実画面で2ノートの列順・ボタン・ダイアログを確認。隔離テスト11項目で3,000バイト境界、上限超過拒否、確定前中断後の重複防止、宛先固定、二重送信拒否、管理者権限を検証。実メールの送信・受信、外部サーバーへの接続は未実施。

- メール送信の宛先はノートのリスト全体を対象に、前後空白と大文字小文字を正規化して重複排除。空欄は除外し、不正形式は送信前に修正を促す。確認画面に件数・全宛先・重複/空欄の除外数を表示する。宛先変更は再確認を要求し、宛先ごとの操作ログで再実行時の二重送信を防止。テスト送信先必須の制限は利用者の明示指示により撤廃。検証はモックで行い、実メールを送信しない。

## 公開側保存先・メール初期値・PDF（2026-10-30）

- 公開フォームと単品ショップは、現在の対象ノートの項目IDに対応した値を `feature_sample_products` に直接保存する。非表示のcheckout_keyで二重登録を防ぎ、列設定の変更は拒否し、追加後に計算・関数を実行する。実フォーム送信と同じ確認リクエストの同時再送で、どちらも1行のみ保存されることを検証。
- フォーム受付ノートは旧データと定義を退避後に削除。旧受付データは新ノートへ自動移行していない。注文受付はSquareの処理中・完了・不確定状態や再課金防止に必要なため、ショップ決済管理（内部）としてメニューから非表示。公開入力値の保存先は商品ノート。
- メール送信の件名・本文の初期値を空欄に変更。利用者から実メールの送受信成功の報告あり。
- PDF一覧はA4横向き。実ボタンの別タブinline表示、PDFのページ寸法と日本語本文を確認。

## 機能カタログ・既存ノートへの適用

`fbp/config/note_feature_catalog.json` が機能ID・表示名・定型文・事前設定・使うSkillの正本。9つのサンプルに加え、最後のotherは任意指示の入口。追加情報はこのカタログと対象ノートの実行時定義を読む。

| 機能ID | 実装の出発点 | 利用者から必要な情報・設定 |
| --- | --- | --- |
| csv_upload / csv_download | feature_samples | 現在の項目・型・順序を自動取得 |
| pdf_list | feature_samples::pdf | A4横・別タブinlineを既定 |
| mcp | mcp_sample_products_* / feature_product_mcp | MCPサーバー有効化・OAuth設定。追加/変更/一覧検索/削除 |
| public_form | public_pages::sample_form | 現在の入力項目・型・並び順。保存先は対象ノート |
| single_shop | public_pages::sample_shop / feature_sample_payment | 商品名・価格（税込円・整数）は必須。Square認証と環境に合う設定 |
| ai_ocr | feature_excel_ocr | OpenAIキー・API URL・画像対応モデル。単件/複数件 |
| mail_send | feature_mail_samples | SMTPサーバー・ポート・送信元、認証使用時のパスワード。全件・重複排除・個別送信 |
| mail_receive | feature_mail_samples / fbp-receive-mail | POP/IMAP方式・サーバー・ポート・認証。保存後確定、サーバー削除なし |
| other | fbp-standard-screen / fbp-dialog | 自由な追加依頼。必要な外部連携設定は実装前に確認 |

Codexは対象ノートの既存クラスと項目を確認し、サンプル専用テーブル名・a/bなどの項目IDをそのまま流用しない。現在の項目IDを業務上の意味に対応付け、列位置に依存しない。既存public_pagesや同名クラスへは必要な関数だけを統合する。単品ショップの入力商品名・税込価格はサーバー側の販売設定へ反映し、購入者のPOSTで上書きさせない。認証情報は取得・複製・依頼本文へ埋込みせず、対象アプリのシステム設定を使う。

「＋」は対象ノートの閲覧権限がある管理者に表示。必要な設定が不足していれば依頼登録を止め、管理者には設定入口、権限のないユーザーには管理者への依頼を案内。依頼には実装・検証・本番リリースの許可を付け、画面でその範囲を明示する。対象ノートの項目定義は利用者の編集文とは別の構造化情報として署名付きで渡す。実データや秘密値は送らない。

- 最終の権限方針：ノート新規作成＋、機能追加依頼＋、データベース形式への変換は管理者限定。非管理者は非表示とし、直接呼出しも拒否。通常の行追加・データ編集は今回の構成操作の制限と分ける。隔離した実CLI環境で両ロールの表示・直接呼出し・ノート不変を検証済み。
