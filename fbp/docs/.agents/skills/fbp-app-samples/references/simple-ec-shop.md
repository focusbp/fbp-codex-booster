# シンプルECショップ / Simple EC Shop

会員登録なしで使う公開ショップと管理側のEC業務をまとめた、独立した再利用テンプレート。
既存の Web Commerce Basic（会員ログイン型）とは入口と対象機能が異なる。
実店舗のデータ、アカウント、接続情報、移行・切替コードには依存しない。

## 含む機能

- 複数ショップとカテゴリー、ショップごとの公開リンク・送料・特商法表記。
- 商品追加・編集、種類1〜5のボタン名／価格／在庫・参加枠、画像。
- 登録した受付種別に応じた商品フォーム、商品一覧、カート、入力・確認・受付完了。
- 申込者と送付先を分けたゲスト受付。異なる種別は別のカートで受付。
- 共通設定のSquareによるカード入力・決済、銀行振込の決済待ち受注。
- 受注と明細、注文日・受注番号のPC折返しなし、申込者／送付先の識別。
- 管理ログイン付きの納品書・領収書、期間指定CSV、全額返金。
- 購入者／ショップへのプレーンテキスト通知。Sandboxは両方とも固定テスト宛先。
- 選択した場合だけ、定期商品・契約管理・カード変更・月次決済とエラー通知。
- 同じ注文・月・返金キーでの重複実行防止。結果不明時は自動再課金しない。

## 受付種別は必要なものだけ登録

正本は選択肢 `sec_product_types`。商品と受注のtype項目で共用する。

| 導入指定 | 固定キー | 初期表示名 |
|---|---:|---|
| `physical` | 0 | 物販 |
| `event` | 1 | イベント |
| `inquiry` | 2 | 問い合わせ |
| `quote` | 3 | 見積依頼 |
| `subscription` | 4 | サブスクリプション |

例えばイベントだけならキー **1だけ** を登録する。キーを0から振り直さない。
表示名は導入先に合わせて変更できるが、キーは業務処理の意味なので変更しない。
未登録の種別は商品追加・編集の選択肢、公開商品、カート、保存・決済で拒否する。
キー4がなければ契約メニューを隠し、定期ジョブとカード登録・変更も拒否する。
削除した種別の過去受注・決済履歴は保持する。選択肢の変更は既存データの削除ではない。

## 導入

既存クラスや同名ノートがある場合は停止し、既存データをリセットしない。
コード配置とテスト環境の定義登録を分ける。設定・商品・受注・認証情報は自動投入しない。

```bash
php fbp/docs/.agents/skills/fbp-app-samples/scripts/install_simple_ec_shop.php --code-root="$APP_SOURCE_ROOT"
```

環境で承認された同期手順に従いソースをテスト環境へ反映した後、Developer Modeで実行する。
省略時の受付種別は物販だけ。

```bash
php fbp/docs/.agents/skills/fbp-app-samples/scripts/install_simple_ec_shop.php --configure-test-root="$APP_TEST_ROOT" --types=physical,event
```

他の例：`--types=event`、`--types=inquiry,quote`、`--types=physical,subscription`。
定義登録はDeveloper Mode以外を拒否する。失敗時は部分登録を確認し、無条件に再実行しない。

### 導入後の設定

1. 管理者（FBPのAdminユーザー）でショップを追加。公開ショップコード、オープン状態、送料、説明文、連絡先、特商法表記を設定する。
2. ショップ配下へカテゴリー・商品を追加。商品ごとの税込額は税別価格と税率から計算する。送料はショップ設定の円額を加算する。
3. Squareを使う場合は共通設定の本番／Sandbox情報を環境ごとに登録する。本番のLocation IDは手入力せずに既定店舗を取得できる。SandboxではSandbox用のLocation IDも共通設定へ登録する。Sandbox情報を本番へ持ち込まない。
4. メールサーバー、送信元、Sandbox固定テスト宛先を設定する。通知テンプレートは `sec_notice`／`sec_test_notice`。
5. 「ショップ運用設定」は単一レコードの標準画面。表示だけでは行を作らず、保存時に作成する。初期は受付・通知・定期処理が無効。検証後に必要なものだけ有効にする。
6. 定期課金はSquare店舗だけを自動処理する。「定期課金開始日」を導入先ごとに設定し、その月より前は処理しない。月額は契約時点の値を保持する。
7. 定期購入を使うときだけ、`simple_ec_cron::run` の毎日6時の確認ジョブを通常のcron設定手順で登録する。インストーラーはOSのcronや外部サービスを変更しない。ジョブは受付・定期処理の設定とキー4が有効な場合だけ動作する。
8. 管理側の公開リンクを使って、公開ショップ・受付・帳票・通知を確認する。実決済は導入先の承認範囲で検証する。

公開入口は `$ctl->get_APP_URL('simple_ec_public','page',['shop'=>$shopCode])`。
公開クラスを名前空間化しているため、既存の `public_pages` クラスを上書きしない。
管理側はStandard Screenを使い、商品・ショップ編集と帳票などだけ既存のダイアログ拡張を使う。

## 構成・正本

- `assets/simple-ec-shop/simple-ec-shop.json`: コード一覧、DB・項目・画面・選択肢・ボタン・通知・定期ジョブの定義。
- `assets/simple-ec-shop/classes/app/`: 移植・改修できるアプリコード。`simple_ec_...` クラスと `sec_...` ノートを使う。
- [DB・画面構成](simple-ec-shop-db.md)
- `scripts/install_simple_ec_shop.php`: 既存クラス・定義を上書きしない導入ツール。
- `scripts/test_simple_ec_shop.php`: API／SMTPモックと実FFMによるオフライン検証。

## 検証

```bash
php fbp/docs/.agents/skills/fbp-app-samples/scripts/test_simple_ec_shop.php --temp-root="$SAMPLE_TEST_TEMP" --framework-root="$FRAMEWORK_FBP_ROOT"
```

新しい一時領域へのコード配置、競合時・不正種別の拒否、全種別の選択・除外、直接指定の拒否、
モックでの銀行振込／Square受付・カード・通知、重複決済防止、返金・定期課金、FFM並行実行を検証する。
外部サービスへ接続せず、メールを配送しない。

実環境では `db_schema`／`standard_screen_check` と公開・管理画面を確認する。
確認済みシナリオ：初回の運用設定保存、種別に応じたフォーム、物販のゲスト銀行振込受付、
イベントだけへの選択肢変更、未使用商品の非公開化・直接受付拒否、定期購入の入力欄追加。
本番Squareの実売上・返金・定期課金やSMTP到達は導入先ごとに確認する。

## 対象外・拡張箇所

- 会員アカウント、会員購入履歴、LINE入口、店舗ごとのSquare OAuth、ショップ担当者別の権限分離。
- 自動配送・送り状・クーポン・倉庫管理。
- 在庫／参加枠は入力数量と設定上限を検査する。自動引当・在庫の増減・失敗注文の予約期限管理は含まない。
- 定期課金成功を新規受注・請求書へ自動展開する処理は含まない。課金結果は決済履歴と契約の前回決済月へ記録する。
- 銀行振込は手動決済の受付。入金確認や継続請求は運用・追加実装で扱う。

これらが必要な案件では、対象機能に応じたSkillとこのテンプレートを合わせて拡張する。
