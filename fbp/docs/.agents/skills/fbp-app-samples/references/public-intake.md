# 公開フォームと管理側受付

`get_APP_URL('sample_public_intake','page')` で公開URLを生成する。お名前・メール・問い合わせ内容を入力し、ダイアログで確認してから保存する。管理者は「サンプル：受付」の標準一覧で内容を読み、対応状態だけを編集する。

公開ページを開くだけではデータを作らない。フォームと確認のトークンはセッションに保持し、期限は最初の表示から30分。確認をやり直すと旧確認トークンは無効になる。同じウィンドウでは最新の入力フローを有効にする。保存対象はセッション上で確認済みの値だけを使う。

フォームトークンのSHA-256を `request_key` として、同じ要求の再送を重複登録しない。FFMのロックを検索から保存まで保持する。保存済みでも期限内の同じ確認要求には完了を返す。完了ページは個人情報・IDを表示せず、管理ノートは未ログインに公開しない。

管理画面で名前・内容・受付日時・request_keyの変更を許可しない。メール送信、自動返信、ファイル添付、公開側の照会・削除は含まない。大量の外部アクセスを想定したレート制限やCAPTCHAは含まないため、実案件で必要な場合に追加する。

## 導入

[共通手順](workflow-samples.md)に従い、`public-intake` を指定する。コードと設定の正本は `assets/public-intake/`。構造は [public-intake-db.md](public-intake-db.md) を参照。

## 確認する操作

- 未ログインで入力→確認→完了まで操作し、管理側に1件だけ登録される。
- 必須・メール形式エラー、確認の取消・再確認、HTML文字列の安全な表示を確認する。
- 別セッションのトークン、期限切れ、確認値の改ざんを拒否し、再送しても増えない。
- PC/スマートフォンで入力・確認・完了表示を確認する。
