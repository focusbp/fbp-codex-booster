# 標準画面のスプレッドシート 基本設計

状態: 基本機能を実装しテスト環境で検証済み。本番反映は未実施。列定義取得スクリプトと取込みCLIも実装済み。完了した検証はdocs/history.mdに記録する。

## 1. 基本構成

- 左メニューの「ノート」の右に＋を配置する。メニュー名の入力・確定でスプレッドシートを新規作成し、メニューを再読み込みする。内部名は自動生成し、入力エラーはダイアログ内へ表示する。

- ノート設定の「画面パターン」に「スプレッドシート」（list_type=4）を追加する。表示切替ボタンと有効・無効フラグは設けない。初版はマニュアルソートのみとし、検索・列ソートは設けない。
- 列はA〜AZの52列、内部項目名はa〜azに固定する。タイトル変更や行・列移動でも対応は変えない。列ヘッダーの移動ハンドルから列の表示順をドラッグで変更し、終了時に保存する。列記号・タイトル・値を一緒に移動し、計算式の列参照は元の項目を参照し続ける。
- 列記号の下をタイトル行とし、その行番号は空欄にする。データ行の番号は1から始める。タイトルは業務レコードにせず列定義として保存する。
- 左端に行番号と移動ハンドルを配置する。行番号は表示位置でありレコードIDではない。ページを切り替えても番号が重複しないよう表示範囲の位置から算出する。
- ノート設定アイコンの下で改行して表を配置する。
- 列記号・タイトル行・行番号を固定し、横スクロールで52列を扱う。行はページ単位で取得する。
- 未使用列も表示するが、タイトルまたはデータの初回保存まで実際の項目は生成しない。
- db_additionalsの上部ボタンをExcel風表示でも利用できる。行ボタンは不要とし、表の各行へ追加しない。
- 初版の対象は標準画面の親ノート。カレンダー・単一レコード・子一覧等への適用は別途設計する。CSVアップロードは後から追加し、初期実装には含めない。

## 2. 見た目とセル入力

- 表には値だけを表示し、テキストボックスや設定ボタンを各セルに常時並べない。白地・薄い罫線・控えめな選択表示とし、数値は右寄せにする。
- 編集可能なセルをクリックすると、その近くに小型の入力ポップアップを1つ開く。見出しにセル位置と項目タイトルを表示する。
- 入力には既存の型別部品を使う。「確定」を入力欄の下に置く。取消ボタンは設けず、閉じる操作は右上の×を使う。幅は通常280〜360px程度を目安にし、長文と画面幅に対応する。
- 「確定」で検証・保存・post_action・計算結果の反映を行い、すべて成功したら閉じて元セルへフォーカスを戻す。画面全体の「保存」ボタンは設けない。
- Escape・右上の×は送信前の入力を取り消す。外側クリックでは未確定入力を失わせず、ポップアップを維持する。送信中は重複確定と取消による状態誤認を防ぐ。
- 単一行入力はEnter、長文はCtrl+Enterで確定する。長文のEnterは改行、日本語変換中のEnterは変換確定だけに使う。Tabはポップアップ内のフォーカス移動に使う。
- ポップアップを閉じた表では矢印キーでセルを選択し、Enter・F2等で入力を開ける。読み上げ用ラベルとフォーカスを保持する。
- 画面端では上・左へ配置を調整し、小画面では中央へ表示する。スマートフォンも表と横スクロールを維持する。
- 「計算」「関数」の列は淡い背景で区別する。データセルは手動編集不可とし、列設定は別の操作として扱う。

## 3. 項目設定と権限

- A〜AZの列記号をクリックすると、直接「項目設定」ポップアップを開く。タイトル行のセルからも同じ設定を開く。
- 基本設定は「タイトル」「型」。整数・小数のときだけ「入力方法（入力／計算）」を表示し、その他の型は入力に固定する。型変更で計算を使えなくなる場合は入力に戻す。関数はプロジェクトサポート専用の内部設定とし、設定済みの列にはその説明だけを表示して通常画面から解除させない。タイトル・型は全員が変更できる。「計算」では簡易計算式・小数桁数・丸め方法を表示する。詳細は第12節に記載する。文字数上限や選択肢等は、必要な型だけの補助設定とする。
- 対象ノートを利用できる全員がタイトル・型を変更し、初回入力による項目生成を行える。別途の管理者権限は要求しない。行データの閲覧・編集・追加・削除は既存ノート権限とDSPに従う。
- Excel列に必須指定は設けない。空欄で保存できる。型・長さの検証は入力値に対して行う。
- 設定の「確定」で即時保存し、表のタイトル・表示形式・編集可否を更新して閉じる。エラーは同じポップアップ内に残す。
- 未使用列の設定を開くだけでは項目を作らない。型・入力方法・式等の指定だけは事前設定として保存し、タイトルまたはデータの保存で項目を生成する。
- 型未指定時はtextとする。値から型を推測しない。データだけ先に保存した場合、内部表示名は列記号とし、タイトル行は空欄を保持する。
- 未使用列の空文字保存では項目を生成しない。0は値として扱う。生成済み項目は、タイトルや全データを消しても自動削除しない。
- 型変更前に既存の全値を検証し、変換不能・桁落ち・切捨てがある変更は拒否する。変更したい人には同じ設定ポップアップ内で理由を示す。
- 自動計算コードが参照する列の型変更も整合性を確認する。計算に必要な型の条件をサポート作成コードと併せて登録する詳細を設計する。既存値の変換可否だけでは計算との互換性を保証しない。
- 選択肢型では、名称の変更・削除ができる一覧と、名称だけの追加欄・登録ボタンを項目設定に表示する。各操作はポップアップを開いたまま保存し、ドラッグで表示順を変更できる。valueは1から増加する整数で自動採番し、削除後も再利用しない。名称変更・表示順変更でvalueを変えない。既存データで使用中の選択肢は削除できず、その場でエラーを表示する。
- 初版の型の候補はtext・textarea・number・float・date・datetime・time・year_month・dropdown。既存型・長さ・選択肢の仕組みを使う。日付はdate型、文字数とDBバイト長は区別する。添付ファイル等の複合型編集は初版対象外。

## 4. 行番号メニューと移動

表下端の＋はダイアログを表示せず末尾へ空行を1件追加し、即時保存・再計算する。

行番号をクリックすると「追加」「削除」「コピー」「ペースト」の小型メニューを表示する。タイトル行はデータ行メニューの対象外。行番号クリックと移動ハンドルのドラッグ開始を分ける。

| 操作 | 動作 |
| --- | --- |
| 追加 | 選択行の直下へ空行を1件追加し、即時保存する案 |
| 削除 | 対象行を示す確認ポップアップで確定後に削除する案 |
| コピー | 保存済みの行の入力値をセッションへ保存する |
| ペースト | 対象行へ貼り付け、即時保存・post_action・再計算する |
| ハンドルで移動 | ドラッグ終了時に行順を即時保存する |

- 行がないときも、末尾の新規入力行からセル入力またはペーストで作成できる。通常の新規入力行への空文字確定だけでは空レコードを増やさない。明示的な「追加」では空行の保存を許可する。
- 行順は内部sort項目で保持し、IDやa〜azの値を入れ替えない。sortは通常の入力項目に出さない。Excel風表示は既存list_typeを置き換えず、専用の順序処理を使う。既存の手動ソートを流用する場合は関連設定との整合を先に検証する。
- 初回の行順は既存一覧順をもとに確定する。新規入力行から作るレコードは末尾へ追加し、行メニューの追加は選択行の直下へ置く。
- 移動成功後に行番号を更新する。競合や保存エラーは操作位置近くのポップアップ内へ表示し、サーバーの確定順に戻す。
- 初版のExcel風表示はマニュアルソート一択とし、検索・列ソートの機能は設けない。行移動はまず同一ページ内とする案。ページをまたぐ移動は操作方式を別途設計する。
- タッチ操作とキーボードでも同じ順序保存処理へ接続できるよう、ハンドルの操作方法を詳細設計する。

## 5. セッションによるコピー・ペースト

- ブラウザーのクリップボードAPIやTSV貼付けは使わない。初版は同一ノート内の行単位で、セッションには最後にコピーした1行を保持する。
- コピーは保存済みの最新値から作る。未確定のポップアップ入力は含めない。閲覧・入力可能なa〜azだけを対象とし、ID・親ID・内部項目・「計算」「関数」の列を含めない。
- コピー元の識別情報、項目と型、値、定義の版、コピー操作の版を保持する。同じログインセッションの別タブでも共有され、最後のコピーで置き換わる。ログアウト・セッション終了で破棄する。
- ペーストはクリックした行へ同じ列位置で貼り付ける。コピー対象の空値も上書きするが、コピー対象外の列・内部項目・計算列を消さない。行の挿入は行わない。
- コピー元と貼付け先の権限・現在の型・定義の版を再確認する。元レコード削除・権限失効・定義変更等は再コピーを案内する。別タブのコピーで内容が変わった場合も版の照合で再操作を案内する。
- 保存値はサーバーのセッションから取得し、クライアント送信値をコピー内容として信用しない。コピー未実行・セッション失効等ではペーストを無効表示する。
- ペースト時は行メニューを処理ポップアップへ切り替え、検証・即時保存・計算・表更新を行う。エラー時はその中で修正・再実行できるようにする。

## 6. 保存・自動計算・エラー

通常のデータセル確定とペーストは、次の順で処理する。

1. 認証、ノート・行・項目の権限、DSP、定義とレコードの版を確認する。
2. 保存済みの最新行へ今回の変更をマージして検証する。未送信の列は消さない。
3. 必要な項目を生成し、統合定義からfmtを生成して形式更新する。
4. 入力値を保存し、簡易計算式を依存順に評価する。各列は設定どおり丸めて保存する。
5. 簡易計算後の行と変更前の値、add/editの種別をpost_actionへ渡し、「関数」の計算を完了させる。その後に最終行を読み直す。
6. 関連するセルを表へ反映し、成功時だけポップアップを閉じる。

- 「入力」は手動編集、「計算」は共通の簡易式エンジン、「関数」はプロジェクトサポートで作成するpost_actionで処理する。「計算」「関数」は手動編集不可。計算コードは空欄を扱えるようにする。
- 手動入力禁止はサーバーでも強制し、標準画面やMCP Note CRUD等の利用者向け保存経路にも共通適用する。post_actionの内部更新は許可し、クライアント指定の解除フラグは作らない。
- フック内のDB更新で同じフックを再帰呼出ししない。計算の依存順と空欄・ゼロ除算等の扱いはプロジェクト側の計算処理に定義する。
- 計算コードが他行や集計へ影響する場合は、保存後の表示更新範囲を広げる。初版は必要なら表示中一覧を再取得して古い計算結果を残さない。
- 行追加はadd、削除はdeleteの既存契約を使う。移動時は通常editを無条件に呼ばず、順序変更を明示するフック契約を詳細設計する。並び順に依存する計算がある場合の再計算範囲を定める。
- 列タイトルだけの変更では業務post_actionを呼ばない。型・入力方法・式・丸め設定の変更後に必要な既存行の再計算は、設定処理として明示的に扱い、表示時に勝手に全件実行しない。
- 入力・権限・競合・保存・計算のエラーは、操作元ポップアップ内に表示する。入力欄ごとのエラー表示先と全体エラー欄を用意し、エラー時に別ダイアログへ遷移したり元フォームを再描画したりしない。
- 計算失敗したセルは表にERRORと表示する。「計算」「関数」の両方に適用し、前回の値を現在の正常値として表示しない。数値項目へ文字列ERRORを保存せず、行・列に対応する計算エラー状態を別管理する。再読込後もERRORを表示する。
- 入力保存済みで計算だけ失敗した場合も、表へERRORを反映し、操作元ポップアップ内に入力保存済みであることと失敗理由を表示する。ポップアップは維持し、通常の未保存エラーと区別する。入力保存を重複させずに再操作できるようにし、外部送信等を伴うフックを無条件に再実行しない。
- エラー列を参照する後続計算列もERRORとし、前回値・0・空欄として計算を続けない。正常に再計算できた列はエラー状態を解除し、結果を表示する。行削除時や入力方法を「入力」へ変更した場合も対応する計算エラー状態を整理する。
- 保存・移動・ペーストは操作IDで再送を識別し、二重登録・二重実行を防ぐ。通信結果不明の場合は操作結果を照会し、成功と仮定したり新規操作として再送したりしない。
- 使用するDBは事前に開き、FFMのロック取得・再取得後に最新値を読み直して判定する。同時初回項目生成、同時追加・移動も競合管理する。独自flockは使わない。
- FFMには複数DBの一括ロールバックがないため、項目生成済み・行保存失敗等の部分完了を区別する。これを含む回復処理は実装時に検証する。

## 7. 標準画面と共通化する仕組み

- Excel風も既存標準画面と同じ項目定義・型別テンプレート・検証を使う。表の構造・余白・配置・入力を開く操作だけを専用層で扱う。
- 現行の一覧は__item_viewer.tpl、検索は__item_search.tpl、追加・編集は__item_edit.tplを使っていることをソースで確認済み。
- Excel風の値表示はfields_view_directと同系列の__item_viewer_notag.tpl、入力はfields_form_directと__item_edit.tplを再利用する。初版のExcel風表示には検索欄を設けない。
- 未生成列やタイトルの入力はfields_form_original、または検証済み仮定義をfield_groupで渡す。入力を開いただけでは項目を生成しない。
- 列定義はまとめて取得し、各セルで定義DBを再検索しない。余白はポップアップのCSSスコープ内で調整する。日付等のJS初期化と型別の表示を実装時に確認する。
- ヘルパーは描画を担当し、保存・post_action・エラー表示先・計算後の更新は別途接続する。
- 既存の検索＋一覧を、一律にセルポップアップ・即時保存へ変更するものではない。

## 8. 列定義と配布

- 基本定義は既存のdb/db_fields、Excel列定義は専用ストレージに分ける。Excel列については専用ストレージを正本とし、同じ値をdb_fieldsへ二重保存しない。
- 専用定義にはノート識別子・列記号・タイトル・型・長さ・選択肢参照・入力方法・簡易式・小数桁数・丸め方法・生成状態・列の表示順・版を保持する。
- 共通の定義取得層で両者を統合し、標準画面・検証・スキーマ参照・fmt生成へ同じ定義を提供する。screen_fieldsとの参照方法も共通化し、画面反映漏れを防ぐ。
- 既存のa〜azがある場合は、有効化時に既存値を保持して引き継ぐ。範囲外の項目は通常一覧で扱う。Excel風に表示しない既存必須項目は既定値等で満たせることを有効化条件とし、制約を勝手に解除しない。
- リリースでは利用先のExcel列定義を配布・置換の対象から外し、基本定義と計算コードを配布する。本番で定義が増減・変更されていても、テスト側の定義で上書きしない。Excel列に付随する選択肢等も保持する。
- Excel列を含む生成済みfmtをテスト環境から本番へそのまま配布しない。本番の現在の列定義と配布された基本定義から、実行時の共通経路で必要なfmtを生成する。コード配布に伴って古いテスト定義へ形式を戻さない。
- 本番で増えた列やタイトル・型の変更を、テスト側の古い定義で上書きしない。サポートによる本番列変更が必要なら明示的な適用差分として扱う。

## 9. プロジェクトサポートと本番設定取得

合意した流れ:

本番で列定義を管理 → プロジェクトサポート開始 → 本番の列定義を取得 → テスト環境へ同期 → 実装・テスト → 本番リリース（本番の列定義は保持）

1. プロジェクトサポート開始時に対象ノートの本番Excel列定義と必要な依存設定を取得する。
2. 対象を限定してテスト環境の列定義と同期し、統合定義とfmtを更新する。既存テストデータを無条件に変換・破棄しない。
3. 必要なテストデータを用意し、画面・入力・保存・post_action・自動計算をAIが検証する。本番業務データの一括取得は既定にしない。
4. コードと基本定義を本番リリースする。Excel列定義とその依存設定は本番の現在値を保持し、テスト環境の値を配布しない。

- サポート開始後の本番列定義の変更を許可する。2026-10-17の追加方針として、DB定義を配布するappリリース直前には本番Excelノートの基本定義・列設定をテストへ必ず取り込む。取得失敗・ID衝突・データ非互換では停止する。版一致を条件とした適用や列定義の専用ロックは設けない。
- 本番の列定義の編集を止めず、リリースでタイトル・型・入力方法・式・丸め設定・生成状態を戻さない。
- post_actionは本番実行時の現在の列設定を参照する。列・型・入力方法が想定と異なる場合は不正な値を書き込まず、通常の入力・計算エラーとして扱う。古い列定義をコードに固定して配布しない。
- 通常のDB保存に既存FFMが使う排他の仕組みは引き続き利用する。本方針は列定義同期やリリースのための追加ロックを不要とするもので、FFM内部のロックを削除する変更ではない。

本番設定取得スクリプトはローカルのscriptsディレクトリへ配置予定。名称はfbp_excel_settings_fetch.sh。ローカルスクリプトとして実装済み。

- 入力: appcode、ノート名、出力ファイル。
- 出力: スキーマ版付きJSON。対象識別情報・Excel表示設定・全列の設定と生成状態・依存定義・取得日時を含む。版や内容ハッシュを記録する場合も参照用とし、リリースの許可条件には使わない。
- 既存の管理APIによる対象解決と認証を使い、本番の読取りだけを行う。認証情報・接続先・業務レコードは出力しない。
- API未対応・不完全応答は失敗とする。途中ファイルで既存出力を上書きしない。専用の取得ロックは作らない。
- 取得とテストへの取込みは別操作とし、サポートの準備手順で連続して実行する。環境間のノートID・選択肢IDの違いを識別名で対応させ、他ノートへ誤適用しない。
- 取込みはExcel列定義に限る同期であり、web側コードをprojects側へ逆コピーする操作ではない。
- 専用ストレージ、取得API、テストへの取込みCLI、配布時の除外、実行時fmt生成を実装する。本番取得APIの実環境での疎通はframeworkの本番配布後に確認する。

## 10. 確定した計算仕様と初版の範囲

- 式が参照する値に空欄がある場合、結果も空欄にする。空欄と数値0を区別する。
- 負数の丸めは、四捨五入ではちょうど半分をゼロから遠ざけ、切り捨てはゼロ方向、切り上げはゼロから遠ざける。-1.25を小数1桁へ丸めると、順に-1.3 / -1.2 / -1.3となる。
- 簡易式の参照先は「入力」「計算」の数値列に限定し、「関数」列は参照不可。関数側は簡易計算後の値を参照できる。
- 初版のExcel風表示はマニュアルソートのみ。検索・列ソートは実装しない。

次は詳細の設計案として扱う: 行移動はまず同一ページ内、式または丸め設定の変更時は既存行を再計算、「入力」へ戻す場合は最後の計算値と再利用用の式を保持、追加は選択行の直下、削除は確認付き、コピーは同一ノート内の1行。

実装側で詰める事項: ページをまたぐ移動の操作方式、順序変更フック、関数列の型条件と再計算範囲、計算失敗・部分完了からの回復、操作ID管理、screen_fieldsの統合、配布時の定義除外と本番値の保持。利用者向けの基本仕様は上記で確定し、これらは詳細設計で扱う。

## 11. 実装時の主な検証

- A/Z/AA/AZの対応、タイトルのみ・データのみ・0・空欄・型だけの事前設定と初回生成。
- 全利用者のタイトル・型変更、既存値と計算の型互換性、必須なし、計算列への不正入力。
- 小型ポップアップ、共通の型別表示と入力、日本語変換、確定時の保存と計算、エラー時の入力保持。
- 行追加・削除・移動と順序保持、クリックとハンドルの分離、競合時の復帰。
- セッションコピー、空値の上書き、計算列除外、別タブ競合、セッション失効、ペースト即時保存。
- 同時初回項目生成・同時行操作・二重送信・通信結果不明・計算失敗と再試行。
- 定義取得とテスト取込み、環境間ID対応、サポート開始後に本番列定義が変わった状態でのリリース、本番列定義と既存データの保持。

動作試験はframeworkテスト環境と隔離した配布試験環境で行う。結果はdocs/history.mdに記録する。

## 列幅

- A〜AZ見出しの右端をドラッグし、操作中は列全体の幅を反映、終了時に自動保存する。列移動ハンドルとは別操作とする。タッチ操作と左右キーによる調整にも対応する。
- 右端のダブルクリックでタイトルと表示中データから幅を自動調整する。
- 幅は各列の`column_width`へpx単位で保存し、全員で共有する。未設定は132px、範囲は64〜1200px。未使用列の幅変更だけでは項目を生成しない。
- 保存時に表全体を再描画せず横スクロール位置を維持する。列移動・項目設定変更でも幅を保持する。
- 本番からの定義取得・テストへの取込みに含め、通常リリースでは本番の幅を置換しない。旧スナップショットで幅が未設定なら標準幅を適用する。

## 12. 入力／計算／関数と丸め設定

| 入力方法 | 値の作成方法 | 手動編集 |
| --- | --- | --- |
| 入力 | セルの入力ポップアップ | 可 |
| 計算 | フレームワーク共通の簡易式エンジン | 不可 |
| 関数 | プロジェクトサポートで作成したpost_action | 不可 |

画面上では関数を選択肢に出さず、整数・小数だけ入力／計算を選べる。既存の関数列は設定済みの説明を表示し、内部modeとセルの手動編集禁止を維持する。整数の計算は小数桁数を非表示・0固定にする。

### 数値型の制約（合意事項）

- 「計算」の出力列はnumber（整数）またはfloat（小数）のみとする。text・date等の非数値型で「計算」を確定した場合は項目設定ポップアップ内にエラーを表示し、設定を保存しない。数値らしい文字列が入っていてもtext型は許可しない。
- 計算で参照する列も数値型のみとし、非数値型を参照する式は設定時にエラーとする。計算が参照している列を後から非数値型へ変更する操作も拒否する。
- 整数型の計算列は小数桁数0とし、小数桁数を増やす場合はfloat型への変更を案内する。明示した丸め方法を適用し、無言の切捨てはしない。

### 式の構文と評価

- 同じ行の列参照A〜AZ、数値定数、+ - * /、括弧、単項の符号、空白に対応する。例はA + B、A * 1.1、(A + B) / C。乗除を加減より先に、括弧内を優先して評価する。
- 列記号は大小文字を正規化し、先頭の=は任意とする案。初版には組込み関数・範囲・別行・別ノート参照を入れない。
- evalは使わず、許可した構文だけを専用解析器で評価する。式の長さ・トークン数・括弧深さに上限を設ける。
- 設定の確定時に構文・参照先・数値型・循環参照を検証する。自己参照、括弧不足、未生成列参照、循環は同じポップアップ内にエラーを表示する。
- 計算列同士は依存順に計算し、各列の丸め済み保存値を次の計算へ渡す。タイトルや表示行番号は参照しない。
- 保存順は「入力値保存 → 計算列 → post_actionによる関数列 → 最終行の再取得 → 表更新」。簡易式から関数列は参照不可とし、設定時に拒否する。
- ゼロ除算・数値範囲超過等は計算失敗として該当セルにERRORを表示し、NaNや無限大、誤った値を保存しない。参照値に空欄があれば結果も空欄とする。負数の丸めは第10節の確定仕様に従う。

### 丸め設定（合意事項）

- 「計算」列に小数桁数と丸め方法（四捨五入／切り捨て／切り上げ）を設定する。式へ丸め関数を書かせない。
- 1列の式を最後まで評価してから、その列の設定で丸め、丸めた値を保存する。演算子ごとには丸めない。他の計算列は丸め済みの値を参照する。
- 途中の任意位置で丸めが必要な処理は「関数」のpost_actionを使う。関数で作る値はそのコードで丸めを明示し、簡易式用の列設定を暗黙適用しない。
- 数値計算の精度、内部表現、割算の精度、保持可能桁数、小数桁数の上限、丸めの既定値は現行フレームワークに従う。Excel風表示のための専用の十進数計算基盤や独自の桁数上限は追加しない。
- 計算列で明示した小数桁数・丸め方法は適用する。未指定時は現行フレームワークの扱いを継承する。負数の丸め方向は第10節の合意どおりとし、実装時には既存処理との対応を確認する。

### 設定変更とサポート連携

- 入力方法・式・丸め設定も全員が変更でき、本番の専用Excel列定義に保存する。本番取得・テスト取込みの対象に含め、通常リリースでは本番の現在値を保持する。
- 既存行を再計算する際は定義の版を揃え、処理中・成功・部分失敗を設定ポップアップ内に表示する。全件原子性は約束せず、回復できる状態を記録する。
- 「関数」を確定する場合は、対象列を計算できるpost_actionの登録を確認する。利用者にコードや任意関数名を入力させず、サポートで準備済みの処理へ接続する。
- サポート側post_actionは列の入力方法を確認し、「関数」に指定された出力列だけを更新する契約とする。「入力」「計算」の列へ意図せず上書きしない。
- 関数の内部依存はプロジェクト側で定義し、二重計算や無制限な再評価を避ける。権限で読めない入力値が計算結果経由で漏れないよう、計算元と出力の可視性も考慮する。

追加の検証: 非数値型の計算指定、数値型以外への変更、括弧と優先順位、単項符号、自己参照と循環、空欄・0・ゼロ除算、正負の丸め境界、連鎖する丸め済み計算、整数型の桁数、設定変更後の全件再計算、計算と関数の実行順、入力への切替、準備されていない関数の指定。

## 計算エラー表示の補足

- ERRORは計算結果の状態表示であり、入力値・型・式そのものの検証エラーとは区別する。非数値型への「計算」指定や不正な式は設定ポップアップ内で拒否し、定義を保存しない。
- 計算エラー状態は業務レコードのIDと列記号に対応付け、エラー理由を保持する。値の型や式の参照先を壊すため、数値型フィールドにERRORという文字列を入れない。
- 共通の表示層へエラー状態を渡し、Excel風表示と通常一覧の両方で古い計算値を正常値として表示しない。ERRORセルから理由を確認するときも、小型ポップアップ内に表示する。
- 関数処理は出力列単位で失敗を報告できる契約とする。予期しない例外で失敗列を特定できない場合は、その処理が担当する関数列をERRORとして扱う。
- 検証対象: 計算・関数の失敗表示、再読込後の保持、エラー伝播、正常再計算後の解除、入力保存済み状態との区別、数値項目へERRORを書き込まないこと。

## db_additionalsの上部ボタン

- Excel風表示でも、既存のdb_additionalsに登録した一覧上部ボタン（place=0）を表示する。
- ボタンの表示条件・権限・並び順・呼出し先・ダイアログ設定は既存の標準画面の処理を再利用する。Excel風専用のボタン登録方式は作らない。
- 上部ボタンに対象行IDや未確定ポップアップの入力値は自動送信しない。対象レコードが必要な処理は、ボタンの呼出し先で対象を選ぶ等の既存方式を使う。
- 行ボタン（place=1）はExcel風表示には表示しない。行単位の操作は行番号の追加・削除・コピー・ペーストと移動ハンドルで行う。通常一覧に登録済みの行ボタン設定は変更しない。
- 上部ボタンがデータ・計算結果を変更した後は、既存の標準的な再読込経路で現在のExcel風表示を更新できるようにする。再読込もノートの画面パターンからスプレッドシートへ直接戻ることを確認する。
- 検証対象: place=0の表示・実行・権限、place=1が表示されないこと、上部ボタンからのダイアログ操作と表の再読込。

## 実装上の保存形式

Excelの数値列も空欄と0を区別するため、実データの固定長形式では文字保存を使い、項目定義と共通入力・計算で数値型を検証する。通常の数値型のFFM読込みでは空欄が0へ変換されるため、この違いをExcelの共通読込み経路で扱う。数値型そのものの意味はExcel列定義に保持する。

実行環境の列定義、計算エラー状態、統合fmtは通常の配布対象外ディレクトリに保存する。直接のFFM/CLI読込みも統合fmtを使い、古い基本fmtで列を落とさない。

## 13. Developer Modeでの編集と同期方向（2026-10-30変更）

Developer Modeの定義変更禁止を解除する。管理者の手動操作、開発パネル、CodexのCLI操作で同じ編集を許可する。以前の保護のためのモード変更・専用の例外許可は不要。

- 列名、型、選択肢、計算式、桁数、丸め、列幅、列順、未生成列への初回入力を変更できる。通常の型検証・計算列の手動入力禁止・権限/DSPは維持する。
- ノートの新規作成と標準画面↔Excel風の画面パターン変更も許可する。開発パネルの保存とCLIの定義操作で同じ動作にする。
- Developer Modeのメニュー＋・Excel→標準変換はローカルで完結し、本番向け予約・同期タスクを送らない。本番の同期受付はProduction Modeの専用経路として維持する。
- 表示だけの検索＋一覧プレビューは、引き続きセッション上の指定として使える。設定変更の代替を強制しない。
- 本番同期は本番→テストへ上書き。開発中の列名・型・列順・画面パターンを本番の現在値へ戻す。ID/名前の衝突やデータ不整合の検出は維持する。
- 定義を含むリリースはテスト→本番へ反映。テスト側で整えたdb・画面項目・Excel settings・生成形式を配布し、直前の本番同期で修正を消さない。
- 定義配布Offと旧形式のリリースZIPは本番のExcel定義を保持する。業務レコード、認証情報、OAuth、計算状態は配布しない。
- 新しいExcel定義配布に未対応の受信側へは送信前に停止する。受信側を更新する手順は環境のリリース手順に従う。
- 本番リリースは今回実施していない。隔離CLIで編集・開発パネル保存・ローカル追加/変換・本番定義上書き、隔離リリースで定義反映とデータ保持を検証した。
