# DSP実装・検証結果

2026-10-08。フレームワークとapp-soshikikaikakuのテスト環境で検証。本番未反映。

## 実装

- DspInterface、DspException、DspReadDecision、DspRuntimeを追加。classes/dsp/registry.phpから対象DBのポリシーを自動解決する。
- ポリシーへControllerとフレームワーク確定のchannelを渡す。必要な関連DBはregistryのdependenciesで事前オープンする。
- Controllerの新規DB禁止ガード、クローズ・ロック解除の抑止、入れ子・例外時の復元を実装した。
- FFMのCRUD、全読み取り経路、行・返却項目・検索条件の検査を追加。内部の生データ取得と公開返却を分離し、更新前後は実際の保存値で判定する。ID一覧を返すmatchもidの返却権限を確認する。
- DSP未定義は既存動作を維持。定義済みの違反・読み込み失敗・判定エラーは停止し、識別子・ルール・理由・channel・実装ハッシュ・追跡IDなどを内部ログに記録する。
- サポートの種別8にDSP策定、種別9にDSP監査を追加。策定は既存の変更許可に従う。監査は許可フラグによらず読み取り専用で、リリース候補に入れない。
- classes/dspのテスト環境同期と配布アーカイブへの包含を追加。DSPを含まない旧アーカイブでは既存ポリシーを維持する。
- fbp-dsp Skillを追加。app-soshikikaikakuの予約ポリシー例はdsp_verificationのテストデータだけを対象にする。既存業務ノートへ認可ルールを推測で追加していない。

## 検証

FFM単体は、固定の条件行列で異なる1,000ケースを実行する。同一ケースの反復やassert数をケース数に数えない。変更前FFMとの比較では返却値・配列形式・データファイルのハッシュも照合する。

| 分類 | ケース数 |
|---|---:|
| DSP未定義の変更前比較 | 250 |
| insert認可 | 100 |
| 読み取り認可・項目制御 | 250 |
| update認可・保存時変換 | 200 |
| delete認可 | 100 |
| 読み込み・判定エラー、ガード、非公開ID | 50 |
| 別プロセスの競合・整合性 | 50 |
| 合計 | 1,000 |

同時実行には索引あり・なしの更新、同時insertのID・件数、同時delete、他人の競合更新拒否を含む。集計とケース一覧は `dsp-test-results.json` に保存する。

app-soshikikaikakuの統合確認は30項目。本人・対象組織の管理者の許可、他人・他組織・匿名の拒否、非公開項目・所有者変更の禁止、関連DB事前オープン、実Controllerのガード、未定義のtask/project参照、MCP主体の受け渡しと成功・失敗後の復元を確認する。予約データは専用の分割領域で作成し終了時に削除する。

Playwrightで管理画面・公開側のchannelを確認し、実際のサポート画面でDSP策定・監査の選択、入力、許可画面への遷移を確認。専用の一時プロジェクトと通知先を用意し、タスクを保存せず終了後に削除した。メール送信・AI実ジョブ起動は行っていない。

追加の回帰確認は既存FFMテスト、MCPスキーマ正規化、DSPアーカイブの包含・隔離領域への適用・旧形式での維持、auto-taskの62テスト、既存タスクAPIの候補・完了・リリース拒否、添付ダウンロード43ケース。監査では変更許可があっても変更・リリースできないことを模擬APIと実行プロファイルで確認した。

## 確認の限界

- MCPのHTTP初期化とツール一覧は実環境で確認。主体の受け渡しは実ハンドラーと仮想設定を使った隔離テストで確認し、保存済みOAuth設定を変更していない。実OAuthトークンを使った認証済みHTTP関数呼び出しは今回実施していない。
- 策定・監査のタスク実行はプロファイル・プロンプト・API状態遷移を隔離テストで確認した。実AIジョブを起動して顧客タスクへコメントする試験は実施していない。
- 標準FFMテストのGit依存の旧比較部分はテスト環境にGit履歴がないためスキップされる。DSP行列の250ケースでは変更前のソースを別プロセスで実行して比較した。
- 意図的な迂回、直接ファイルアクセス、保守操作による迂回、OS隔離は合意どおり対象外。

実行結果の最終値と検証したソースのハッシュは `dsp-test-results.json` を参照する。個別アプリでの業務ポリシーの策定と本番リリースは別工程。
